# A 股助手（astock-plugin）使用说明

**定位一句话**：你自己在券商 App 下单，这个插件负责**选、算、记、盯**——选出该买什么、算清买多少股与挂什么价、记下实际成交、盯计划外的风险。**它不连接券商、不下单、不含任何委托通道。**

## 0. v2.8.3 修复：两处「看起来配了、其实没生效」的静默错

这两处都不是崩溃，而是**返回值正常、数字也在，但语义是错的**——所以能活很久。

### ① 计划里的阈值键探针根本不读（改了什么都不会发生）

| 项 | 内容 |
|---|---|
| 现象 | 计划的 `probe_config` 里能写 `stop_loss_pct` / `take_profit_pct` / `trailing_pct` / `drop_alert_pct` / `rise_alert_pct` / `volume_ratio_alert`，但探针装配 `HintsConfig` 时**只读插件设置页**，从不读计划 |
| 后果 1 | 在计划编辑器里改这 6 个阈值 → **完全不生效，且没有任何报错**（最坏的一类失败：以为定了纪律，其实没生效） |
| 后果 2 | `astock_watch status` 每次还刷一句「未识别键…探针不会读」，让你以为配置坏了（实际生效的是设置页的值） |
| 根因 | 同一段函数里两套取值语义：`pick()` 是「计划优先、设置页兜底」，而 hcfg 那段循环只写了 `own.get(...)`——两层语义没贯彻到底 |

**修法**：读取点改为 `pick(key, getattr(hcfg, key))`，与 `pick()` 的注释一致。

配套（不然只是「能生效但改不了」）：

- `PROBE_KEYS_READ` 直接取 `hints.PLAN_OVERRIDE_KEYS`（= `HintsConfig` 全部字段），
  与实际读取点**共用同一份事实源**，不再靠两处手工同步——这正是「配置生效、
  `status` 却说无效」的成因；
- 补上写入口：`astock_watch action=set_rules stop_loss_pct=3` 也能改阈值；
- `status` / `action=plan` 新增「阈值（计划覆盖 > 设置页 > 默认）」三层表，
  标明**哪个值在生效、设置页的值被谁压过**。

> **一个反向坑（已避）**：「启动盯盘」会把设置页的阈值镜像进计划。读取点修好之后，
> 这份镜像会在计划层压过设置页，于是“改完设置页没反应”会以另一种形式复现。
> 所以三层表必须存在——让不一致**可见**，而不是藏起来。需要单计划覆盖时，
> 显式用 `set_rules` 写，此时才是“计划优先”的正常语义。

### ② 看板首行把「持仓收益率」写成「当日涨跌幅」

| 项 | 内容 |
|---|---|
| 代码 | `astock_board.py`：`pct = pct_change(price, cost)` ← **相对成本**的收益率 |
| 文案 | 「卡片首行＝现价/涨跌幅」← 声称是**当日**涨跌幅 |
| 实测 | 天山铝业 cost 11.97、现价 12.19 → 显示 +1.84%；而当日实际是 **-0.57%** |
| 后果 | 看到的涨跌方向可能**与行情相反**（已发生多次，一度被误判为行情源问题） |

**修法**：不是二选一，而是两个都写、各带标签——

```
12.19　持仓 +1.84%　｜　今日 -0.57%　｜　1000 股 · 成本 11.970 · 浮盈 +220.00 · 可卖 1000
```

`持仓` 相对成本（对持仓更有用）、`今日` 相对昨收（与行情一致）。
行情没带 `change_pct` 时显示 `今日 -` 占位，**绝不拿成本收益率顶替**。

## 0.000 v2.7.0 新能力：`astock_business` —— 门槛②不再是永久缺口

**背景**：选股方法论四道硬门槛的第②道是「相关业务收入占营收 ≥ 5%」。
这道门槛此前一直被登记成「工具链无分部财报字段 → 永久缺口」，
结果是**每次简报都只能写「②无法核实 → 只观察」**——门槛事实上不存在：
回购/增持类事件讲不清"哪块业务受益"，所有标的都卡在同一句免责声明上。

现在直接读东财 F10 主营构成（`emweb.securities.eastmoney.com/PC_HSF10/BusinessAnalysis`），
字段 `MBI_RATIO` 就是该项收入占营业收入的比例——**正是门槛②要的数字**。

### 判定有四档，不能混

| 结论 | 含义 | 对门槛② |
|---|---|---|
| `pass` | 相关分部占比 ≥ 5% | 通过 |
| `below` | 有该业务，占比 < 5% | 不通过 |
| `absent` | **分部表里根本没有这块业务** | **不通过，且比 below 更确定** |
| `na` | 事件属回购/增持/分红等资本运作 | **不适用**，不据此否决 |
| `unknown` | 数据取不到（北交所/ETF/接口异常） | **不等于通过** |

### 为什么 `absent` 是关键洞察

分部披露有**重要性门槛**。进不了分部表，说明该业务占比远低于披露线，
必然远小于 5%。襄阳轴承（000678）就是活例——它的分部表只有
「轴承 83.68% / 等速万向节 12.92% / 其他 3.40%」，**没有机器人**。
这比事后查到"机器人业务占营收 0.023%"更早、也更少歧义地证明了同一件事：

```
$ astock_business code=000678 event="襄阳轴承 人形机器人 减速器"
结论：FAIL 不过（无此业务）
理由：分部表与经营范围中均无「机器人/减速器/谐波」相关业务
```

`absent` 是**否定证据**，`unknown` 是**数据缺失**。把这两者混为一谈会得出
完全相反的结论——这是实现时最容易写错的地方，已在单测里锁死。

### 为什么 `na` 必须单独存在

回购、增持、分红是全体股东受益的资本运作，不对应任何具体产品线。
若把它算成「查不到 → 不通过」，门槛② 会变成"任何资本运作标的都永远过不了"，
等于自己废掉一条通道。

### 匹配的两个坑（都踩过）

| 坑 | 现象 | 修法 |
|---|---|---|
| **泛词误判** | 事件说「电池材料回收」，泛词「电池」命中 69% 的「动力电池系统」→ 判 PASS。但问的是"回收"，不是动力电池 | 关键词按同义词表顺序（具体→泛）取首个命中 |
| **公司名污染** | 「锡业股份」含「锡」，问锌业务的新闻也会命中「锡」→ 把 4.9985% 的锌判成 50% 的锡锭 | 提取关键词前**先把公司名从事件文本剔除** |

另外「其中:xxx」这类带前缀的子项会被排除——它是父项的拆分，
拿子项占比当主业会把 50% 的锡锭判成 4.94%。

### 顺带修掉的数据层缺口：gzip 没解压

东财 F10 即使请求头没有 `Accept-Encoding` 也返回 **gzip 压缩体**。
原 `_http_get` 只做 `decode` 不解压，`json.loads` 报
「接口返回的不是 JSON（可能被反爬拦截）」——**错误信息指向了完全错误的方向**
（以为是反爬，实际只是没解压）。

已在 `_http_get` 统一处理 gzip / deflate / br，并用 `1f 8b` magic 做无头兜底。
这个修复对**所有**东财接口生效，不只是主营构成。

### 用法

```
astock_business code=002273 event="汽车电子AR+业务放量"     # 单只判定
astock_business codes=["002532","512890","600900"]           # 批量体检
astock_business code=000678 keywords=["机器人","减速器"]      # 手动指定关键词
```

> ⚠️ **数据边界**：北交所（BJ）与 ETF 无分部披露，接口返回「股票代码不合法」→ `unknown`。
> 报告期按中报/年报披露，**不是实时**——给的是"最近披露的业务结构"。

## 0.00 v2.8.0 修复：K 线多源链——再也不会"天天没 K 线"

### 事故经过（2026-11-04）

那天 `web.ifzq.gtimg.cn` 回 **501**、`push2his.eastmoney.com` 回 **Empty reply**，
而插件当时只有这两家做源。结果不是"有点慢"，而是**K 线、均线、选股、回测
全部停摆**，工具只能回一句「接口限流，等 30 秒再试」——等一天也没用。

### 根因：同厂商的多个域名不算备源

原来的设计是「腾讯主源 + 东财备源」，看起来是双源，实际有两个问题：

| 问题 | 说明 |
|---|---|
| 单域名 | 腾讯只写了 `web.ifzq` 一个入口。它被限流时，`ifzq.gtimg.cn`、`proxy.finance.qq.com` 明明还通 |
| 备源长期不可用 | 东财 `push2his` 已经持续回 Empty reply，等于**没有备源** |

### 现在的源链

```
腾讯（3 个域名轮换） → 雪球 → 东财
```

- **腾讯 3 域名**：`ifzq.gtimg.cn` / `web.ifzq.gtimg.cn` / `proxy.finance.qq.com`，
  逐个尝试，任一成功即返回；
- **雪球**（第二厂商）：唯一同时支持 前复权/后复权/不复权 + 日周月分钟 的
  免费源。需要先取 `xq_a_token` cookie（进程内复用 30 分钟，失效自动重建）；
- **东财**：仍保留作最后兜底，不指望它。

### 两条容易踩的实现口径

1. **成交量单位**：雪球给「股」，腾讯给「整手」。转手时用 `int(x+0.5)` 而不是
   `round()`——`round` 是银行家舍入，`1150268.5` 会变 `1150268` 而腾讯是
   `1150269`，同一根 K 线换源后量能对不上，看起来像数据漂移；
2. **返回根数**：腾讯某些域名会多给 1 根，统一截断到 `limit`，否则"换源前后
   均线值变了"会被误读成行情漂移。

实测三个场景（日/周/60m × qfq/none/hfq）雪球与腾讯 **OHLCV 逐字段完全一致**。

### 附带能力：雪球补齐了成交额

腾讯日 K 不返回 `amount`（只有量），雪球返回。现在换到雪球时 `Bar.amount`
有值，东财源同样有——只有腾讯源缺，这是数据源差异不是 bug。

### 源失败记忆

某个源整体失败后进 120 秒冷却，排到链尾。回测要连发几十次 K 线请求，
不这样做每次都要在挂掉的源上白等一轮超时。

### 回归测试（`TestKlineMultiSource`）

4 条断言钉住这次的教训：源链必须跨三家厂商、腾讯必须有多域名、
主源全挂时备源能接管、三家全挂时**报错要点名三个源**而不是笼统说"等 30 秒"。

## 0.0 v2.6.1 修复：`astock_sentiment code=portfolio` 一调必炸

**现象**：`astock_sentiment code=portfolio`（组合舆情报告）必报

```
UnboundLocalError: cannot access local variable 'report'
where it is not associated with a value
```

而**单票模式完全正常**。

**根因是变量遮蔽，不是网络、不是台账路径**：

```python
import astock_report as report              # 模块级别名

async def _tool_sentiment(self, args):
    if code_raw.lower() == "portfolio":
        return await report.build_report(...)   # ← 走这里必炸
    ...
    report = senti.summarize(...)           # ← 函数内有赋值
```

Python 的规则是：**函数体内只要出现对某个名字的赋值，该名字在整个函数内都是局部变量**。
所以 `report` 在整个 `_tool_sentiment` 里都是局部的，走 portfolio 分支时它**还没绑定**
→ `UnboundLocalError`。单票模式走的是赋值**之后**的分支，所以一切正常，
常规用例根本覆盖不到——这也是它藏了很久的原因。

**修法**：局部结果改名 `rep`（`astock_mixin_sync.py`，+9/-5 行）。

**回归防护**（3 个用例，防同一个坑再犯）：

| 用例 | 检查什么 |
|---|---|
| `test_no_function_shadows_module_alias` | 全插件 AST 扫描「模块级别名 ∩ 函数内赋值 ∩ 函数内 `NAME.attr`」**三重交集** |
| `test_sentiment_branches_do_not_shadow` | `_tool_sentiment` 专项：只比对模块级别名，不误报 `out.append()` / `scope.strip()` 这类局部对象 |
| `test_regression_rep_alias_present` | 固化断言：源码不得再出现 `report = senti.summarize` |

> 扫描逻辑对所有插件模块通用。写第一版时判据过宽（把所有局部 list/str 的属性访问
> 也算进去），一口气误报 4 个名字——**收紧为只与模块级别名取交集**才正确。

### 为什么持仓是「一票一卡」，但进度条只在有风险时才画

v2.5.5 起**每只持仓都有一张 kpi 卡**（用户原话："我让你每一个持仓一个卡片"）——
表格虽然更省空间，但卡片才能让涨跌走 `trend` 通道（▲绿/▼红），表格里只能是黑字。

| 形态 | 单只高度 | 何时出现 |
|---|---|---|
| kpi 卡 | ≈60px | **每只持仓恒定**（涨跌有红绿）|
| 风险原因行 | ≈20px | 触发规则 / 超仓 / 距止损余量 <30% |
| 进度条 | ≈40px | 同上（只在有风险时）|

进度条不常驻：每只票两条满绿进度条等于没有信息还占地方。它承担的是
**"离出事还有多远"**——语义是安全余量（触线 = 0 红短条，安全 = 100 绿满条），
反过来喂「已消耗量」会让"最危险"显示成"最健康"（v1.7.2 真实踩过）。

风险原因另起一行写在卡片下面，**不塞进 kpi 的 note**——note 会被前端省略号截断。
判定沿用 `astock_hint` 的同一套规则（不另立标准，避免"面板说没事、
hint 说该卖"自相矛盾），另加一条 `hint` 没有的**提前预警**：
距止损余量 < 30% 就开始提醒——`hint` 只在真正**跌破**阈值时才喊，
那时候往往已经晚了。

### 为什么"跑输/跑赢"比"赚了/亏了"重要

| 情形 | 绝对涨跌 | 真实结论 |
|---|---|---|
| 大盘 -1%，持仓 -0.5% | 亏钱 | **实际跑赢 0.5pp**（结构是对的）|
| 大盘 +2%，持仓 +1% | 赚钱 | **实际跑输 1pp**（选股有问题）|

只看"赚了亏了"会把这两种情况判断反。这也是唯一能回答
「**我亏的是市场的钱，还是我自己的钱**」的方式。

### 背离提示（最有信息量的部分）

指数会骗人：上证红盘可能只是几只权重股拉的。

| 现象 | 面板会怎么说 |
|---|---|
| 指数涨 > 0%，但上涨个股 < 45% | ⚠️ 指数被权重股拉动，多数个股在跌，别把红盘当普涨 |
| 指数跌，但上涨个股 > 55% | ⚠️ 是权重股拖累指数，多数个股在涨，别被绿盘吓到 |

### 数据源与性能（面板每 5 秒刷新，必须算清）

| 数据 | 来源 | 实测耗时 |
|---|---|---|
| 主要指数 | 腾讯 `qt.gtimg.cn`（批量一次）| ~0.2s |
| 涨跌家数 | 东财 `f104/f105/f106`（**单次请求**）| ~0.15s |

**关键取舍**：涨跌家数本可以"拉全市场快照再数"，实测要 **5.3 秒**——
面板 5 秒刷一次，直接卡死。所以改用专门的统计字段（单次 0.15 秒），
并加 **15 秒 TTL 缓存**：面板刷 3 次才真实请求 1 次，
接口失败时**保留上次有效值**（宁可显示 15 秒前的数，也不显示空白）。

### 一个必须记住的口径坑

## 0.1 计算公式库：`astock_calc`（v2.4.0）

把常用公式**固化成可复算的调用**，不再需要手算、也不需要临时写脚本。
底层的 `astock_formula.py` 是**零网络纯函数**（可单测、可被选股引擎复用），
`astock_calc` 只负责取数与渲染。

### 六个 mode

| mode | 算什么 | 什么时候用 |
|---|---|---|
| `summary` | 均线/偏离/RSI/年化波动率/动量/区间回撤/区间位置 | 看一只票的技术全貌 |
| `ma` | 只算均线 + 偏离 + 位置 + 多头排列 | **盘后重算规则价**（改规则前先跑） |
| `rule_check` | **价位规则体检**：方向是否可达 + 均线漂移 | **每天收盘后**（能抓出死规则） |
| `cost` | 盈亏平衡价/止损止盈价/盈亏比/可买股数 | 下单前算账 |
| `adjust` | 除权影响估算（不复权均线虚高多少） | 标的刚除权时 |
| `ratio` | 收益/回撤比 | 选策略（先看回撤再看收益） |

### 几条口径（写死在函数里，改不了）

1. **缺数据返回 `-`，绝不用 0 代替。** 0 在"低波动""低估值"这类因子里是
   **最优点**，会把数据不足的标的推到第一名——这是最典型的静默错误。
2. **价格 round 2 位，均线/比率 round 4 位。** 均线截成 2 位会让"偏离是否
   >1%"的判定失真。
3. **均线看复权（qfq），成交价看原始（raw），两者不可混用。**
4. **只做统计，不预测。** 任何输出都不含"会不会涨"。

### 例子：下单前算账

```
astock_calc mode=cost entry_price=11.97 shares=200 buy_fee=5 stop_pct=8 take_pct=15
```

会给出一条常被忽略的结论：**「涨回成本价 ≠ 回本」**。10 元买 100 股，
成本 10.00，实际盈亏平衡价约 10.02 —— 那 0.02 是来回手续费。

### 例子：选策略看回撤

```
astock_calc mode=ratio total_return_pct=98.33 max_drawdown_pct=-50.05
```

收益/回撤比 = 1.96。换成 `85.28 / -17.75` 得 4.80——**收益低 2 个点的那套，
风险调整后好 2.4 倍**。回撤大的策略即使累计收益更高，你也可能在中途就
扛不住卖掉，实盘拿不到回测的数。

## 0.3 操作指示（v2.0.0，傻瓜化的最后一步）

不想看任何数字，只想照着做：

```
给我操作指示
```

输出是一份**可以直接照抄进券商 App** 的清单：

```
第一步：卖出（先做这个，才有钱买）
  600000  卖出 1000 股 @ 9.78   浮亏 -13.18% 触发止损线 -8%
  000001  卖出  500 股 @ 11.49  单票占比 54.0% 超上限 25%，减半

第二步：买入（卖出成交后再做）
  002354  买入 1500 股 @ 8.46   止损 7.78 / 止盈 9.73
  300296  买入 1600 股 @ 6.65   止损 6.12 / 止盈 7.65

操作后现金：27,361.70 元
```

### 为什么顺序固定「先卖后买」

A 股卖出资金**当日即可用于买入**。反过来先买会因资金不足失败。
所以顺序不是建议，是资金规则。

### 卖出只依据明确规则，不做主观判断

| 规则 | 动作 |
|---|---|
| 浮亏触发止损线 | 全部卖出（最高优先级） |
| 浮盈触发止盈线 | 减半锁利 |
| 不在本轮选股名单 + 浮亏 | 换仓（腾资金给更好的标的） |
| 单票占比超上限 | 减到上限内 |

每条都带**原因**，你能核对「为什么让我卖这只」。数量已按 **T+1 可卖**裁剪——
给出卖不掉的数字等于给废单。

> **占比的分母是「账户总资产」= 持仓市值 + 可用现金**，不是持仓市值。
> 这个口径很重要：只持一只股时，「占持仓市值」恒定 100%，会把 24% 的正常仓位
> 也报成「超上限」并让你无谓减仓（v2.0.1 已修）。现金多、仓位轻的账户
> 尤其要看这个口径对不对。

### 关于「连接账户」

> **本插件不连接券商、不下单、不生成委托文件。** 它只产出给人看的操作指示，
> 执行动作始终由你在券商 App 完成。

这不是暂时没做，是刻意的设计取舍：对接券商需要 miniQMT 权限或 UI 自动化
（后者极易失效），且会引入真实资金风险。当前版本的定位是
**「告诉你按哪些按钮」，而不是「替你按按钮」**。

## 0.4 本地历史存档（v2.0.0）——让回测窗口能变长

免费接口的历史深度是**硬上限**（641 根日 K ≈ 2.6 年），不足以覆盖一个完整牛熊。
唯一不依赖付费源的解法是**自己每天把数据存下来**：

```
更新 K 线存档
```

| 项目 | 说明 |
|---|---|
| 存哪只 | 默认台账持仓 + 自选股，也可指定代码 |
| 存多久 | 每只最近 640 根（约 2.6 年） |
| 存什么口径 | **不复权原始价**（关键，见下） |
| 占多少空间 | 约 24KB / 只 / 年 |
| 怎么自动 | 跑回测时顺手存（设置页可关） |

### ⚠️ 它不会立刻变长

**今天开始存，一年后才会多出一年。** 存档是时间的函数，没有捷径。

现在存的覆盖约 2.6 年（就是接口能给的上限）；随着每天更新，
明年这个时候回测窗口就有 3.6 年。这是唯一能免费突破接口限制的办法。

### 为什么只存不复权价

前复权价格会随每次分红/送股**重算整段历史**——今天存的 2024 年价格，
明年分红后会变成另一个数字。直接存前复权会导致：

- 存档里同一日期有两个不同价格，而代码无法分辨哪个是「当时的真相」；
- 跨期拼接后自相矛盾；
- 最坏是**静默错误**：数据看着有，结果是错的。

所以存档一律存**不复权**（raw）价，且 `(code, date, adjust)` 三段主键让两个
口径并存、互不污染。回测读取时按口径取，绝不跨口径混拼。

### 清理保护

`prune` **必须**指定日期或代码，无参调用直接拒绝——几年数据不能被误点清空。

## 0.5 策略是实测调过的，结果很诚实

v2.0.0 用真实历史（2024-03 ~ 2026-10，25 只活跃股，57 期）跑了参数对比，
**实盘结论和最初的设计假设不一样**：

| 策略 | 推荐率 | 累计收益 | 最大回撤 | 和基准比 |
|---|---|---|---|---|
| momentum 动量 | 45.6% | -12.1% | -28.8% | **跑输**（基准 +7.7%）|
| reversal 回归 | 36.8% | -44.0% | **-51.6%** | 大幅跑输 |
| quality 价值 | 47.4% | +9.4% | -17.8% | 基本持平 |

**必须说清的三点**：

1. **这段行情里三套策略几乎都跑不赢沪深300**。这是真实结果，不是 bug。
   我给不出「稳赚」的策略——那样说就是骗人。
2. **`quality` 是唯一正收益且回撤最小（-17.8%）**。它涨得慢，但亏得也少。
   如果你受不了 -28% 的回撤，它是更现实的选择。
3. **`momentum` 权重已按实测调整**：60 日动量权重从 0.14 提到 0.30、
   20 日从 0.26 降到 0.12。实测「拉长动量周期」比「堆技术形态」有效
   （胜率 49.1% vs 42.1%）。短线动量噪声太大。

### 参数实验记录（可复现）

| 实验 | 结果 | 采纳 |
|---|---|---|
| mom60 主导 vs 基线 | 胜率 49.1% vs 42.1%，累计 +0.9% vs -11.3% | ✅ 改权重 |
| 调仓 10 日 vs 5 日 vs 20 日 | 10 日最好；20 日胜率仅 28.6% | ✅ 默认 10 日 |
| 每期 1 只 vs 3 只 vs 8 只 | 1 只累计最高但回撤 -31%；3 只回撤 -18.8% | ✅ 默认 3 只（控回撤） |

**这些结论只对这段历史成立**。2.6 年不够一个完整牛熊，换一段行情可能完全不同。

### 一句话用法

```
帮我选股
```

你会拿到一份**可以直接照着填单**的清单（v2.2.0 起是富围栏版）：

- **指标卡**：扫描 5,576 只 → 过门槛 12 只 → 可买 2 只 → 计划投入 3,296 元
- **卡片看板**：`天娱数科 8.24`｜400 股 ≈ 3,296 元（占权益 3.5%）
  止损 7.58 / 止盈 9.48 · 得分 88.4
- **明细表**：标的 / 参考价 / 股数 / 金额 / 占比 / 得分 / 止损 / 止盈

股数是按你的**可用资金 + 单票上限 + 整手规则 + 费用**算出来的，不需要你自己除。

> **为什么不是一张大表**（v2.1.x 的做法）：8 列表格在窄屏会挤成竖条；而
> "先看三件事（扫了多少 / 能买几只 / 要花多少）→ 再看买什么 → 最后核对明细"
> 才是真实的阅读顺序。所以拆成 `kpi` + `board` + `table` 三段。
> 宿主不渲染富围栏时，围栏内容会显示为 JSON 代码块——数字仍可读，不会空白。

### 三套策略（因子方向相反，按市况选）

| 策略 | 选什么 | 什么时候用 | 风险 |
|---|---|---|---|
| **momentum** 趋势动量 | 站上均线 + 中期动量为正 + 放量 + 接近区间高点 | 趋势市、牛市 | 震荡市会被假突破反复打脸 |
| **reversal** 均值回归 | 跌到区间低位 + RSI 超卖 + 低波动 + 估值不高 | 震荡市、超跌反弹 | 逆势低吸，可能继续下跌（务必带止损） |
| **quality** 质量价值 | 低 PE/PB + 大市值 + 低波动 + 换手适中 | 长期持有、不想盯盘 | 涨得慢，牛市跑输 |

**这不是"选一个终身用"**。趋势市跑 momentum、震荡市跑 reversal——这是使用层面的判断，插件不替你判断市场状态（猜错市场状态的代价比不做更大）。

### 在右栏面板看策略（v2.1.0 起：一个 tab 看三套）

右栏是 **「持仓 / 选股」两个 tab**。「选股」tab 是**卡片看板**（v2.2.0 起，
不再是缩进纯文本）：一票一卡，卡上直接写「买多少股 @ 什么价」+「止损 / 止盈」，
下面两根进度条分别表示**得分在池内的位置**与**仓位空间**；共识标的（被多套
同时选中）标绿，顶部 chips 直接点名是哪几只。

**为什么窄栏必须用卡片而不是文本列表**：331px 宽度下，`　天娱数科 400股 @8.24
（得分 88）` 这类全角缩进行三套策略长得一模一样，扫不出「这只被两套同时选中」
这个**唯一有价值的信号**。卡片能把「名称/价格/股数/止损」四项折成两行，
再用 `prob` 通道画进度条——条越长越靠前，不用读数字。

**为什么不分成三个 tab 各看各的**（v2.0.x 的做法）：宿主的右栏面板是**只读**的
（Markdown 与 lite-tree 都点不了），面板本身无法触发扫描。而设置页按钮
原先一次只跑一套策略 → 另外两个 tab 永远显示「尚未生成」，要改设置再点三次
才能完成一次对比。既然对比才是选股的真正诉求，就该让它在**一屏**内成立。

> **一次扫描、三套结果**：三套策略的差异只在过滤条件与打分权重（纯 CPU），
> 贵的部分（1 次全市场快照 + 30 次 K 线）三套完全共用。所以现在点一次
> 「立即跑一轮选股」，成本与只跑一套几乎相同，却能同时填满三套结果。
> 更关键的是**价格同源**——分别扫出来的三套价格不同源，横向对比时
> 「这只动量第一、那只价值第三」可能只是几十秒价差造成的假象。

### 面板为什么有时是空的

**面板只读缓存、不会自动扫全市场**。这是刻意的：一次扫描要拉 30 只 K 线（受限速约 6-8 秒），而面板每 5 秒刷新一次——同步跑会把界面拖死，还会把公共行情接口打到限流。

要生成结果，二选一：

- 对话里说「帮我选股」（推荐，能看完整报告）
- 设置页点「**立即跑一轮选股**」（一次跑完三套）

生成后，三个策略的结果在 3 分钟内都可以在「选股」tab 里看到。

### 「该用哪套？」——插件直接给结论（v2.1.1）

看到三个推荐率百分比后，"所以呢？"才是真问题。现在插件会把它翻成一句话：

```
当前无优势策略，建议轻仓。相对最好的是 趋势动量（D 档·历史 49% 跑赢基准，
57 期样本）——追强势，趋势市有效；震荡市容易被假突破打脸。

⚠️ 最好的那套也没到「可考虑」档：与其重仓赌一套，不如轻仓参与。
⚠️ 均值回归 历史最大回撤 52%——用之前先想清楚能不能扛。
```

三档结论（规则固定，可核对）：

| 情况 | 结论 |
|---|---|
| 有 A/B 档 | 点名最优 + 次选，说明各自性格 |
| 全是 C/D 档 | **当前无优势策略，建议轻仓**（这是实测常态，不粉饰） |
| 样本不足 8 期 | 明说"测不准"，**不给结论** |

> **措辞是硬约束**：推荐率是**策略的历史表现**，不是任何一只股票上涨的概率。
> 所有输出都带这句声明，测试专门锁住它（`test_never_says_win_probability`）。
> 另外 reversal 即使排第一也会强制附警告——它实测表现最差，而用户往往只看排名。

### 对话里也能一次看三套

说「**三套策略对比一下**」（或「哪个策略更合适」），会带上 `compare=true`：

- 一次采集、三套结果，成本与只跑一套几乎相同；
- 每套给前 5 只 + 各自的推荐率；
- 额外标出**被多套同时选中**的标的。

默认问「帮我选股」仍只跑一套——多数时候你只想看一个结论，三套一起摆
反而要你自己挑。要看分歧时再明确说「对比」。

### 推荐率（v1.9.0）——从回测里跑出来，不是拍脑袋

**推荐率 = 历史上按这套策略选股，跑赢沪深300 的期数占比。**

它来自真实历史数据的逐期回放，不是主观打分。做法是把策略放回近 2.6 年，
每 10 个交易日调仓一次、每次买 3 只，一期一期记账：

```
帮我回测一下动量策略
```

真实跑出来的结果（2024-03 ~ 2026-10，57 期 / 20 只标的）：

| 策略 | 推荐率 | 平均每期超额 | 累计收益 | **最大回撤** | 档位 |
|---|---|---|---|---|---|
| momentum 动量 | 63.2% | +3.59% | 最高 | **-46.9%** | B 可考虑 |
| reversal 回归 | 54.4% | +2.20% | 中 | -32.7% | B 可考虑 |
| quality 价值 | 57.9% | +0.99% | 低 | **-24.0%** | B 可考虑 |

**看这张表要注意两件事**：

1. **动量收益最高，但回撤也最深（-46.9%）**——只看收益会以为它最好，
   实际是"赚得多也跌得狠"。这就是为什么必须同时报最大回撤。
2. **三套都是 B 档**。没有一套是 A 档（≥65% 胜率）——这是诚实的结论，
   不是每套策略都值得重仓。

### 分档规则（样本不足一律降档）

| 档位 | 条件 | 含义 |
|---|---|---|
| A 推荐 | 胜率 ≥65% 且样本 ≥12 期 | 历史上多数期跑赢基准 |
| B 可考虑 | 胜率 ≥50% 且样本 ≥8 期 | 略优于基准，可用但别重仓 |
| C 谨慎 | 胜率 ≥35% 且样本 ≥8 期 | 时好时坏 |
| D 不建议 | 其余 | 含**样本不足** |

**样本不足一律降到 D**。哪怕胜率 100%，只要只有 3 期样本，也只显示
「样本不足」——因为 3 期样本在统计上什么也证明不了。不做这个降级，
用户会看到「胜率 100% · 推荐」然后重仓，这是最危险的功能设计。

### 回测的三个限制（不写清就会变成误导）

1. **历史只有约 2.6 年**（641 根日 K，接口硬上限）。这**不够一个完整牛熊**。
   所以结论只能说"在这段时间里有效"。
2. **幸存者偏差，无法消除**。能取到历史的都是活到今天的股票；这期间退市的
   不在样本里。这会**系统性高估**收益。所以结论一律用**相对基准**表述，
   并且每次都标注这个偏差。
3. **quality 策略回测不完整**。PE/PB 只有当下快照、没有历史序列，所以它的
   估值因子没参与回测，只用市值/波动/换手回放。报告会明确标注"不完整"。

### 防未来函数（回测可信与否的分水岭）

逐期回放时，每个时点**只喂入该日及之前的数据**；买入价用**次日开盘**
（不是当日收盘——收盘时你还没下单）。

这条不是理论洁癖：一旦用了当日收盘价买入，回测收益会明显虚高，而且
**从结果上看不出来**——这是量化回测里最常见的自欺方式。测试里专门锁住了
这一点（`test_entry_is_next_day_open_not_signal_close`）。

反向验证也做了：构造一只"前 250 天横盘、最后 50 天暴涨"的股票，
若回测正确，早期调仓期不该选中它。实测早期各期收益仅 -0.3%（横盘扣费），
暴涨段才被捕获——说明确实没用未来数据。

### 股票池是怎么选的（回答"池子从哪来"）

这是最容易含糊的地方，所以逐步写清。**选股（实盘）与回测的池子规则不同**：

**实盘选股（`astock_pick`）的池子：**

| 阶段 | 做什么 | 规模 |
|---|---|---|
| ① 全市场快照 | 按**成交额降序**取前 300 只（成交额是最直接的流动性代理） | 全市场约 5500 只 → 300 |
| ② 拉日 K 算技术因子 | 从这 300 只里再取前 30 只 | 300 → 30 |
| ③ 硬门槛过滤 | ST / 涨停 / 跌停 / 成交额不足 / 历史不足 60 根 | 30 → 候选池（通常 5-20） |
| ④ 多因子池内打分 | 每个因子转成**池内百分位**，加权成 0-100 分 | 候选池内排序 |
| ⑤ 仓位分配 | 按分数分预算 → 整手 → 最多 N 只 | 通常 1-5 只 |

**为什么从成交额开始**：成交额 < 1 亿的股票买得进卖不出，而且一两笔单子
就能拉动价格。先按成交额筛是最稳的第一道网——但这也意味着
**它会系统性地漏掉小盘冷门股**，这是刻意的取舍，不是 bug。

**回测池的规则更小且不同**：取成交额前 25 只，且**只有这一个来源**（为了速度）。
所以回测结论反映的是"在大中盘活跃股里选股"的效果，不代表能选出小盘黑马。

> **注意活跃度偏差**：今天成交额靠前的股票，2.6 年前未必活跃。这个偏差
> 无法用现有免费接口修复，所以在回测报告里明确标注，不假装不存在。

### 得分是什么，不是什么

> **得分 = 候选池内的相对排名（0-100），不是上涨概率，也不是预期收益。**

85 分的含义是「在今天的候选池里综合排在前 15%」。为什么不给概率：收益分布没有已知参数、样本外失效是常态，任何"上涨概率 73%"这类数字都没有数学基础，编出来比不给更危险。

每只都会给出**得分来源**，你能看清它是靠什么进来的：

```
天娱数科(002354) 得分 89.7
· 20日动量(17.28%)→贡献 26.0
· 均线多头排列(3档)→贡献 16.7
· 60日动量(61.3%)→贡献 14.0
```

如果一只票是靠「低市净率」进来的，而你不认可这个逻辑，那就该跳过它——**黑箱评分没法这么用**。

### 资金怎么分配

1. 本轮预算 = min(可用现金 × 使用比例, 现金 − 保留下限)
2. 按分数降序逐只分，每只不超「单票上限 × 总权益」
3. 换算成整手（科创板 200 股起），先留 0.2% 给费用
4. 买不起一手 / 受上限截断剩下的预算，**回收后按分数再分给已入选的**
5. 最多买 N 只

第 4 步是实测教训：不做回收时「8 万预算只投出 5 万」，剩 3 万躺在账上没人知道为什么。

### 过门槛的规则（不满足直接不进候选池）

- ST / 风险警示股一律排除
- 当日**涨停不追**（成交不确定）、跌停不接
- 成交额低于门槛（默认 1 亿）→ 流动性不足，买得进卖不出
- 历史数据不足（不足 60 根日 K）→ 算不出可靠技术因子
- 当日涨幅超上限（momentum 设 9.5%）→ 不追高

每次跳过的原因都会明确写出来，不会静默消失。

### 相关设置项

| 设置项 | 默认 | 说明 |
|---|---|---|
| 默认选股策略 | momentum | Agent 未指定策略时用哪套 |
| 选股范围 | main | main＝沪深主板+创业板（避开北交所低流动性） |
| 本轮最多买几只 | 5 | 分散度。设 1 是集中押注 |
| 现金使用比例 | 80% | 留 20% 给 T+1 补仓与误判余地 |
| 保留现金下限 | 0 | 与使用比例取更严格者 |
| 最低成交额门槛 | 1 亿 | 流动性下限 |
| 技术面分析只数 | 30 | 每只 1 次请求、限速 5 次/秒 → 约 6 秒 |

## 1. 五分钟上手

### 第一步：配置（设置 → 插件 → A 股助手）

首次使用只需改 3 项，其余保持默认：

| 设置项 | 建议值 | 说明 |
|---|---|---|
| **台账文件路径** | 留空 | 默认存在 `<工作区>/.astock/ledger.sqlite`。想跨项目共用一份台账时填绝对路径 |
| **佣金率 / 最低佣金** | 按你券商实际填 | 默认万 2.5、最低 5 元。**这一项填错会让成本价和盈亏全都失真** |
| **止损线 / 止盈线** | 8% / 15% | 决定条件单参数与提示阈值 |

### 第二步：录入现有持仓

对每个持仓，让 Agent 录入一笔买入（用你**当初真实的成交价**）：

```
帮我录入持仓：浦发银行 600000，2000 股，成本 9.20，2026-09-15 买的
```

Agent 会调用 `astock_record`，先返回**预览**（费用明细、成本价变化），你确认后落账。

### 第三步：看持仓

直接问：

```
看下我的持仓
```

会在对话里出一张三栏看板：**需处理 / 持有中 / 无需关注**。

卡片首行的两个百分比**口径不同，都带标签**（v2.8.3 起）：

```
12.19　持仓 +1.84%　｜　今日 -0.57%　｜　1000 股 · 成本 11.970 · 浮盈 +220.00 · 可卖 1000
```

- `持仓 +1.84%`：相对**你的成本**的收益率（对持仓决策更有用）；
- `今日 -0.57%`：相对**昨收**的当日涨跌幅（与行情软件一致）。

> 早先只显示一个**没标签**的百分比，而文案说它是「涨跌幅」——实际取的是成本收益率。
> 于是浮盈的股票在下跌日会显示成红的（方向与行情相反），已误导过多次。

## 2. 日常怎么用（三种场景）

### 场景 A：晚上 5 分钟，挂好条件单

这是**最重要**的用法。你没时间盯盘，所以让券商替你盯：

```
给我 600000 的条件单参数
```

你会拿到可照抄的参数块：

```
【浦发银行 600000】卖出
  委托价  9.53
  数量    2000 股
  条件单：
    止损触发价 8.47（跌破自动卖出）
    止盈触发价 10.58（涨到自动卖出）
  计划号  P20261025-1
```

**在券商 App 里挂"条件单/止盈止损"**，把这三行填进去。挂完之后白天完全不用看盘。

> 计划号用来事后对账：成交回单会自动匹配到这条建议，告诉你实际成交价与建议价差了多少。

### 场景 B：成交后同步回系统

下单成交后（无论是条件单自动触发还是你手动买的），**不用逐笔手抄**：

```
（把券商 App 的成交明细整段粘进来）

证券代码,证券名称,买卖标志,成交价格,成交数量,成交金额,手续费,成交日期
600000,浦发银行,卖出,9.60,1000,9600.00,5.10,2026-10-25
688256,寒武纪,买入,900.00,200,180000.00,45.00,2026-10-25
```

或直接说：

```
帮我把这段成交同步进台账
```

系统会自动：解析多笔 → 匹配建议计划 → **校价**（偏差超 2% 标黄）→ 落账更新成本与 T+1。

**识别不出的行会明确列出**，不会猜——因为记错一笔成本，后面所有盈亏都是错的。

### 场景 C：随时问一只股票

```

```

输出**七类证据清单**（不是情绪打分）：

| 类别 | 可靠度 | 说明 |

| 公司公告 | 法定披露 | 硬事实 |
| 龙虎榜 | 客观数据 | 席位买卖 |

## 4. 盯盘与通知

### 盯盘（自动按交易时段作息）

```
启动盯盘
```

**不需要你设闹钟**，它自动遵守 A 股时段：

| 时段 | 是否盯 |
|---|---|
| 工作日 9:10–9:15 | ✅ 准备 |
| 9:15–11:30 | ✅ 盯（含集合竞价） |
| 11:30–13:00 | ❌ 午休跳过 |
| 13:00–15:00 | ✅ 盯（含尾盘） |
| 15:00 之后 / 周末 | ❌ 不盯 |

**非交易时段零 token 消耗**——探针直接返回"无变化"，不会唤醒模型。

### 看 / 改「到底在盯什么」（v2.3.1）

盯盘规则（精确价位、代码范围、信号类型、报告级别）**只存在于计划级
`probe_config`**，设置页 schema 里没有这些键。v2.3.1 之前这是两个死角的叠加：

- `astock_watch status` 的体检表只读 interval/enabled/last_run，**从不读
  `probe_config`** → 规则内容看不见；
- 工具没有写入口 → 模型只能回"请到右栏「盯梢」页手动改"。

现在补了三个动作：

```
# 看：体检（含「在盯什么」摘要）+ 完整规则
astock_watch action=status      # 体检表 + 规则摘要 + 范围兜底说明
astock_watch action=plan        # 完整规则清单 + 原始 probe_config JSON

# 改：三种写法（都只动给出的键，其余保留）
astock_watch action=set_rules rules=[...]                 # 整体替换
astock_watch action=set_rules add_rules=[{...}]           # 追加
astock_watch action=set_rules remove_rules=["000651"]     # 按代码删除
astock_watch action=set_rules remove_rules=["600900"] \
    add_rules=[{...600900 新规则...}]                     # 同代码＝替换（v2.5.9）
astock_watch action=set_rules add_rules=[...] min_level=urgent   # 同时调级别
astock_watch action=set_rules stop_loss_pct=3                    # 调阈值（v2.8.3）
```

**同代码 `remove_rules` + `add_rules` ＝ 替换**（v2.5.7 修正）：`remove`
**只作用于已有规则**，本次 `add_rules` 进来的新规则一定保留。返回值会写
「✅ 已替换盯盘规则」并点名哪几只被替换——而不是笼统的「已写入（共 N 条）」。

> 历史缺陷（2026-11-03）：早先执行顺序是「先 extend(add) 再按 code 过滤
> remove」，于是同代码的 remove 把**刚加的新规则一起删了**，净效果是该代码
> 规则整条消失；而 `len(new_rules)` 与返回值都是对的，从返回值完全看不出问题。
> **所以改完规则请用 `action=plan` 回读**——`status` 只显示条数。

`set_rules` 的四条安全语义（每条都对应一种真实误操作）：

1. **只动给出的键**——改一条止损价不会把你配的 codes/kinds/min_level 清空
   （整体覆盖 `probe_config` 的症状是"只改了个价位，其他提醒全没了"）；
2. **先校验再写盘**——非法规则（缺 code/price、op 写错）直接报错，不落半截配置；
3. **保留指纹基线**——走 `ensure_plan` 的合并语义，不会因为改规则就把当前
   所有信号当"新变化"重报一遍；
4. **`remove` 只删已有规则**——同代码 `remove` + `add` 是替换，新规则一定保留
   （v2.5.7 修）。返回值会点名被替换的代码，不再只报一个看不出语义的条数。

**阈值也能从这里改**（v2.8.3）：`stop_loss_pct` / `take_profit_pct` /
`trailing_pct` / `drop_alert_pct` / `rise_alert_pct` / `volume_ratio_alert`
六个键可以写在计划里，**写进去就优先生效**（压过设置页）。所以：

- 想**临时收紧**纪律（如这几天止损从 8% 调到 3%）→ 写进计划，用完删掉；
- 想**长期改** → 改设置页，别写进计划（否则计划里的旧副本会一直赢）。

三层谁在生效，`action=plan` / `action=status` 里有一张「阈值（计划覆盖 >
设置页 > 默认）」表逐行摊开；设置页的值被压过时会明确写「设置页 X 被压过」。

> 需要操作**非 astock 的盯梢计划**（邮箱、网页、命令、其他插件）时，用通用
> 插件 `watch-plugin`：`schedule_list` / `schedule_get` / `schedule_upsert` /
> `schedule_run` / `schedule_delete`，任何盯梢源通用。

盯什么（四类优化）：

- **A 股时段信号**：集合竞价异动（9:15–9:30）、开盘跳空（9:30–10:00）、尾盘异动（14:30–15:00）
- **条件单去重**：你已挂条件单的止损/止盈**不再重复提醒**（券商会自动执行，催你也没用）
- **分级报告**：`urgent` 只报紧急 / `action` 默认 / `info` 全报
- **去重限流**：同一信号 6 小时内只提醒一次

### 精确价位规则（v2.1.4，原 ruthless-watch 的能力已并入）

百分比阈值表达不了"**跌破前低 36.01 清仓**""**放量站回 37.11**"这类技术位——
你不知道该以哪个价做基准。所以在 `probe_config` 里可以直接写死价位：

```json
rules: [
  {"code": "000651", "name": "格力电器", "kind": "stop_loss",
   "price": 36.00, "op": "lt", "label": "跌破前低 36.00 清仓",
   "severity": "urgent"},
  {"code": "000651", "kind": "rebound", "price": 37.11, "op": "gt",
   "vol_ratio_gt": 1.2, "label": "放量站回 37.11"}
]
```

| 字段 | 说明 |
|---|---|
| `op` | `lt` 跌破 / `le` 触及 / `gt` 站上 / `ge` 站上（含等于） |
| `vol_ratio_gt` / `vol_ratio_lt` | 可选量能附加条件：放量 / 缩量才触发 |
| `once_per_day` | 同一信号当天只报一次（**默认 true**） |
| `severity` | `urgent` / `action` / `info`，决定是否发邮件 |

#### 配好后确认「会不会真的发邮件」

价位规则的 `severity` 决定它属于哪一档，而**邮件有一个单独的阈值**：
低于阈值的信号只会显示在面板里，不会发邮件。价格突破类规则通常是
`action` 档，如果在设置页把「通知阈值」留在 `urgent`，就会一条邮件都收不到。

所以配完规则后，说一句「**看盯盘状态**」，体检里会直接告诉你：
- 有 `⚠️ 邮件阈值会把部分信号拦掉` → 按提示把「通知阈值」调低；
- 有 `🔴 上次探测有信号被邮件阈值拦掉` → 说明确实发生过，同样按提示调整。

规则请在**设置页或计划编辑器**里改，不要手改配置文件——运行中的应用以
内存中的配置为准，手改会被覆盖，且不会报错。

> **为什么 `once_per_day` 默认 true**：价位条件是**持续满足**的——跌破
> 36.00 后只要不涨回去，每 5 分钟探测都会命中。不去重就是每小时 12 封邮件
> （正好撞上限流上限，然后一整天都不再报新信号）。
>
> **为什么并入 astock 而不是独立插件**：两者做的事高度重叠，独立后行情获取、
> 时段自律、去重、邮件通知都得重做一遍；而且只继承 `WatchSource` 的插件
> **不会出现在插件管理页**（用户以为没装上）。合并后还多了台账上下文
> （邮件里能带上"持仓成本、浮动多少"）与统一的邮件/去重链路。

### ⚠️ 价位规则会**静默失效**：每天收盘后跑一次体检（v2.4.0）

规则写下去之后**不会自己保持有效**，而且**失效时没有任何报错**。实测踩过三种：

| 失效方式 | 真实案例 | 后果 |
|---|---|---|
| **方向写反** | 格力配「跌破 38.60」(`lt`)，但收盘 38.52 **已在下方** | 要么立刻误触发一次、要么被当天去重吃掉，**此后永远不响** |
| **价位漂移** | 天山减仓线挂 11.55（当时的 MA10），三天后 MA10 已到 11.593 | 规则价偏低，**要多跌一点才触发**，保护悄悄变弱 |
| **标的已清仓** | 已卖掉的格力仍留着"清剩余 100 股" | 纯噪音，占着提醒名额 |

界面看不出、日志不报错——**只有把现价代进去算才知道它是死的**。所以：

```
astock_calc mode=rule_check              # 自动读当前盯盘计划体检
astock_calc mode=rule_check rules=[...]  # 或显式传规则
```

输出会逐条给出：方向是否可达、距触发多远、均线漂移几 %、建议改成什么价。

**还有一条同样容易错的：均线的复权口径。**

格力 2026-08-27 除权「10 派 20 元」（每股 2 元）。用**不复权**原始价算 MA60，
除权前的价格被算高了 2 元，均线整体**虚高约 0.9 元**（会算成约 39.4，
真实前复权 MA60 是 38.545）——验证线差点因此设错。

| 用途 | 该用哪个口径 |
|---|---|
| 均线、区间高低点、回测 | **qfq 前复权** |
| 止损价、止盈价、成交价、成本 | **raw 原始价**（你申报的就是这个价） |

> 两者**不可混用**。`astock_calc mode=adjust prev_close=41.58 dividend_per_share=2`
> 可以估出"不复权算 MA60 会虚高多少"。

### 盯盘计划：插件自己建（v2.1.1，无需手动）

说一句「**启动盯盘**」就够了。插件会同时做两件事：

1. 打开插件侧开关（探针被调用时才干活）；
2. **自动创建/维护宿主的盯梢计划**（`source=astock`，默认每 300 秒）。

于是「点了启动、结果什么都没发生」这个老问题没有了。附加保障：

- **幂等**：重复启动不会建出第二条计划；
- **自愈**：计划被删、被禁用、或切了工作区，插件重载时会自动修复；
- **暂停不删**：暂停盯盘是**禁用**计划而非删除——删掉会丢失指纹基线，
  恢复时会把当前所有信号当"新变化"重报一遍（邮件轰炸）；
- **体检**：说「看盯盘状态」会告诉你卡在哪一环，并附**最近一次探测**
  的时间与结果（"它真的在跑"比"计划存在"更让人安心）。

> **拿不到宿主能力时**（旧版 lite-work / 非正常启动），插件会**如实说明**
> 并给出手动步骤（右栏「盯梢」页 → 新建计划），绝不假装成功。
>
> **不需要碰系统 crontab**。计划编辑器里的「cron」模式（`*/5 9-14 * * 1-5`）
> 是**宿主内置的调度格式**，和系统 `crontab -e` 毫无关系。

### 高风险邮件通知

想在不在电脑前时收到提醒：

1. 先配好 **email-plugin**（邮箱账号/密码或 OAuth2 授权）
2. 本插件设置页把「高风险邮件通知」设为开启
3. 点「发送测试邮件」验证

**凭据沿用 email-plugin**，不需要重复填。通知阈值默认 `urgent`（只发止损/跌停/尾盘跳水这类）。

> **建议保持 urgent**。阈值调成 info 会让邮件变成骚扰，最后你会关掉它。

**邮件不是独立进程**：它由盯盘探针在发现信号时**顺带发出**（探针跑一次 → 有信号才发信）。
所以上面的盯梢计划是邮件通知的前提——计划没建，探针不会被调度，一封邮件也不会发出来。
「收不到邮件」的排查顺序：① `astock_watch action=status` 看「现在是否在盯」；
② 设置页点「发送测试邮件」验证通道；③ 看阈值与 `mail_to` 是否填对。

> **pick 是决策引擎**（多因子打分 → 算出股数），后两者是**信息检索**

## 6. 设计上的几个"为什么"

这些是刻意的取舍，不是遗漏：

**为什么不下单？**
任何形式的委托通道都需要对接券商（miniQMT 需开通权限、UI 自动化极易失效），且会引入真实资金风险。你自己下单、插件记账提示，是风险最低且最稳定的分工。

**为什么选股给的是"池内相对排名"而不是"上涨概率"？**
收益分布没有已知参数、样本外失效是常态——"上涨概率 73%"这种数字没有数学基础，编出来比不给更危险。相对排名可核对、可复现，失效时还能定位到是哪个因子拖的后腿（每只都给因子贡献明细）。这是刻意选的**诚实但不好卖**的方案。

**为什么每只票都要列出得分来源？**
因为用户必须能判断"该不该信这一条"。如果一只票是靠"低市净率"排进来的，而你不认可这个逻辑，就该跳过它——黑箱评分没法这么用，也不知道失效时该改哪里。

**为什么面板不自动跑选股？**
一次扫描 = 1 次全市场快照 + 30 次 K 线请求，受限速约 6-8 秒；面板 5 秒刷新一次。同步跑会拖死界面、并把公共行情接口打到限流。所以面板只读缓存，扫描由你显式触发（说一句话或点一下按钮）。

**为什么三套策略是「一个 tab 内的对比」而不是三个 tab？**
宿主右栏面板是只读的（Markdown 与 lite-tree 都点不了），tab 切换是协议内唯一的交互方式——但 tab 切换**换不来「对比」**：三套结果分在三个 tab 里，你得来回切四次才能比出差异，而差异正是选股决策的唯一依据。v2.0.x 的「三个 tab」还有个更硬的伤：面板不能触发扫描，而设置页按钮一次只跑一套，于是另外两个 tab 永远是空的。v2.1.0 改成一次采集三套 + 一个对比视图，既省掉两次切换，也把分歧摆在了同一屏。做成下拉框仍然是死控件（看着能选、点了没反应），这条没变。

**为什么买不起一手的预算要回收重分？**
实测过不做回收的版本：8 万预算只投出 5 万，剩 3 万躺在账上。原因是某只高价股买不起一手、它那份预算没人接手，而这个原因藏在细节里——用户只会觉得"算错了"。现在回收后按分数再分给已入选的，实测能投出 99%。

**为什么不同策略的因子方向是相反的？**
momentum 追强势（动量高、接近高点得分高），reversal 抄超跌（处于低位、RSI 超卖得分高）。这两者在同一批股票上的排序**必然相反**——如果它们的因子构成相同，那三套策略就是同一件事，拆成三个名字反而是骗人。测试里专门锁住了这一点（`test_opposite_directions_documented`）。

**为什么条件单参数算得这么细？**
止损价避开整数关口（9.00 → 8.99，避免被"扫一把"）；不低于跌停价（否则当天根本不可能成交）；止盈价**不按涨停裁剪**（涨停只约束当日成交，不约束目标价——否则会出现"止盈价低于现价"导致条件单一挂就成交）。

**为什么不给情绪打分？**
把公告、研报、热榜合成一个 0-100 分，会掩盖这些信号可靠度差几个数量级的事实。拆成证据清单 + 背离提示，你才知道该信哪一条。

**为什么盯盘不报已挂条件单的信号？**
重复催促没有意义，还会把真正的新信号淹没。

**为什么持仓面板不用表格、反而用一行行短句 + 刻度条？**
右栏只有 331px 宽，6 列表格会被挤成竖条（数值竖着排一列，读不出来）。改成
「每股 2 行」后每行都短，再补一条 `36.91├──────●──┤37.29` 的刻度条表达
"现价在区间里的位置"——**窄栏里"读得出来"比"行数少"重要**。

**为什么 lite-tree 里拿 `prob` 字段画刻度条？**
不是伪造概率。宿主面板里 `options[].prob` 是**唯一会被渲染成图形**的字段
（label + 彩色横条 + 百分比），于是把它当可视化通道复用，表示"仓位占比 /
距止损的余量"这类 0-100 的刻度。这是宿主能力所限的变通，**别当 bug 改掉**。

## 8. 常见问题

**Q：成本价和券商 App 显示的不一样？**
A：先检查设置页的佣金率与最低佣金是否填对。券商 App 的成本价口径各异（有的含预计卖出费用，有的不含），本插件按"买入金额 + 买入费用"计算。

**Q：可以改已录错的流水吗？**
A：可以。`astock_portfolio action=trades` 查到流水 id，再用 `action=delete_trade` 删除，插件会**按剩余流水重算**成本价。

**Q：可用资金为什么不会自动扣减？**
A：出入金（银行转账）插件看不到。手动校准：`astock_portfolio action=set_cash`。

**Q：为什么提示"当前不盯盘"？**
A：正常。非交易时段（周末/午休/收盘后）主动跳过，不消耗 token。
体检结论此时应显示「全链路就绪，当前不在盯盘时段」，**不会**说开关是关闭的
——那是 v2.1.4 的误报（把收盘当成故障），已在 v2.2.0 修正。

**Q：配了价位规则，面板也有提醒，但一封邮件都收不到？**
A：先看**邮件阈值**。探测级别和邮件级别是两个独立开关，默认还不一样
（探针 `action` / 邮件 `urgent`），`severity: "action"` 的规则会被邮件阈值
全部拦掉且**不留任何日志**。到 `astock_watch action=status` 看有没有
「⚠️ 邮件阈值会把部分信号拦掉」这条——有就按它说的把设置页「通知阈值」
调到 `action`。v2.3.0 起这种情况会在日志里打 warning，并在体检里显式点出。

**Q：设置页改了配置（限流速率 / 超时 / 缓存 TTL / 台账路径），要重启吗？**
A：**不用**。v2.3.0 起本插件实现了宿主的 `on_config_changed` 钩子，保存即生效：
行情参数（限流速率、HTTP 超时、报价与 K 线缓存 TTL）会立即重新应用，台账与
存档句柄也会置空、下次取用时按新路径重建。盯盘开关不在此列——它由
`astock_watch start/stop` 与设置页按钮维护计划状态，而探针每次探测都现读配置，
本来就不需要重建。

**Q：手动改了 `config.json` 里的 `rules`，为什么不生效？**
A：运行中的 lite-work 以内存配置为准，宿主会把磁盘改动**回写覆盖**。
改用计划级 `probe_config.rules`（宿主 `PATCH /api/schedules/{id}`）或
设置页保存。详见「精确价位规则」一节的「坑 2」。

**Q：电脑关机/应用退出时，邮件还会发吗？**
A：**不会**。邮件不是独立进程或云端服务，它依赖 lite-work 应用内的定时
探针。应用退出、机器休眠期间不探测、不发信；恢复后按 `catch_up` 策略补一次。
想让提醒可靠送达，要么保持应用运行，要么同时用系统级提醒（如 macOS
提醒事项）做兜底。

**Q：舆情显示某类"数据缺口"？**
A：该类接口暂时不可用或该标的确实没有该类数据（如小盘股没有研报）。报告会如实列出，不会用 0 充数。
